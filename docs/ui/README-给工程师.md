## 三、落地前必须知道的四件事

### 1. 原型不是代码库，是行为说明书

`prototype.html` 是单文件，靠三个 CDN 脚本跑起来：

```
react@18.3.1/umd          react-dom@18.3.1/umd          @babel/standalone@7.29.0
```

也就是说：**打开需要联网**，而且 JSX 是浏览器里实时编译的，没有构建、没有工程结构、没有状态管理。它的价值在于「点一下看它怎么反应」，不是拿来改的。

请照它的交互和排版重写，不要试图把它接进工程。

### 2. 原型字号是按 412 宽画布写的，直接搬到真机会偏小

原型里正文集中在 **11.5–13px**，最多的一档是 11.5（40 处）。这是桌面 412px 画布下的视觉等效值。

真机上 412dp 宽的屏，正文应该落在 **14–16sp**。换算下来大概要上调 2–3sp 才能对上眼感。**请按 Android 规范的字号体系重建，再用截图比对视觉，不要照抄 px 值。**

其余尺寸可以直接用：

- 画布基准 412 × 892，内容区边距 上 14 / 左右 18 / 下 26，卡片圆角 20–24，按钮圆角 18，主按钮高 54
- 主标题 22–26，卡内标题 14–15，正文 12–13，辅助说明 11–11.5，全屏提醒的时间数字 74
- 最小点击区不小于 48dp

### 3. 小狗素材的分辨率有硬上限

这条影响交付质量，请务必先看：

原图是 1279×1230 的四行四列，切出来**单格只有约 255×273 像素**。`final/` 的 512 画布是把身体归一到 424 像素后的结果，放大了约 1.9 倍，属于插值。

所以真实清晰度上限是：**身体约 220 × 220 物理像素**。

| 展示尺寸 | @2x 需要 | @3x 需要 | 实际可用 | 结论 |
|---|---|---|---|---|
| 96dp（列表、详情） | 192px | 288px | 220px | 勉强够，@3x 会略软 |
| 136dp（响铃页） | 272px | 408px | 220px | 不足，@3x 明显软 |
| 238dp（空状态） | 476px | 714px | 220px | **远超规格，必糊** |

**建议空状态的小狗降到 140dp 以内**，或者让画师单独重出这一张 1024 的高清图。响铃页 136dp 也建议降到 120dp 左右。

### 4. 动画素材 8.7MB，安卓上不建议直接当资源用

16 个 WebP 动图，full 6.2MB + small 2.5MB，单个 300–430KB。安卓对动图 WebP 的支持要做兼容判断，且这个体积进 APK 不划算。

**更合适的做法是用代码做，效果一样，体积接近零**：

```
静态 PNG + 属性动画
pivotY = 脚底位置（画布 476/512 ≈ 93%，显示时对应 size × 0.93）
scaleY：1.000 → 1.018 → 1.000，周期按姿态取 2.6–3.4s，ease-in-out
scaleX：1.000 → 0.994 → 1.000，同周期反向，近似体积守恒
```

如果嫌整缩放太假，可以再叠一层：平移幅度 1.5px 左右，只作用在头部区域（用 `ObjectAnimator` 分两段，或者直接上 Lottie 把 `anim/full` 的帧序列导进去）。

原型里就是这么做的，见 `dog/anim_breathe.py` 的实现思路。如果需要我自己用代码实现的原型版本，可以再给一版。

如果一定要用动图，**只带 `small/` 那套（2.5MB）就够**，`full/` 那套分辨率也没余量，性价比低。

## 四、设计 token

### 色板 · 颜色等于触发源

| 用途 | 色值 | 说明 |
|---|---|---|
| 夜底 | `#18213A` | 全局背景。实际是 `linear-gradient(168deg, #1B2540 0%, #18213A 42%, #212C4C 100%)` |
| 卡片 | `#26335A` | 比底色亮两档，不用描边分层 |
| 卡片高亮 | `#2E3C68` | 主卡、按下态 |
| 弹层 | `#212C4A` | 底部上滑弹层 |
| 轨道 | `#3A4874` | 路径未达成段 |
| 正文 | `#EDF0FF` | 主文字 |
| 次级文字 | `#B9C2E0` | 副标题、备注 |
| 辅助文字 | `#A6B1D6` | 说明、时间戳 |
| **时间** | `#9BE0CC` | 薄荷，触发源一 |
| **Wi-Fi** | `#BAC3FA` | 薰衣草，触发源二 |
| **地点** | `#F4D0A8` | 蜜桃，触发源三 |
| 按钮文字 | `#17273F` | 亮色底上的深字 |

三种触发源的颜色**贯穿列表、新建、详情、全屏提醒四处**，不是装饰，是信息本身。不要换成单色。

全暗色是场景给的：通勤提醒集中在早晚，地铁口、车库、卧室，都是弱光环境。

### 路径组件 · 核心信息载体

这是这一版最关键的一个组件，规则只有五条：

1. **段数 = 启用条件数**。只用时间就只画一段，不假装有三段。
2. 达成的段用该触发源的色，未达成留暗轨 `#3A4874`。
3. 白点是「此刻」，停在最后一个达成点上。
4. 列表行里退化成**节点序列**（小圆点加短线），一行就能看出有几个条件、几个已满足。
5. 宽度小于 200dp 时标签全关，只留点和线。

### 动效

| 场景 | 时长 | 曲线 |
|---|---|---|
| 页面进入 | 300ms | ease，位移 14px |
| 底部弹层 | 340ms | cubic-bezier(.32,.72,0,1)，从 100% 上滑 |
| 全屏弹窗 | 380ms | 同上 |
| Toast | 280ms | ease，位移 12px + scale .97 回正 |
| 小狗弹入（换姿态） | 420ms | cubic-bezier(.34,1.56,.64,1)，带轻微过冲 |
| 小狗跳动（响铃页） | 1.1s × 2 次 | cubic-bezier(.36,.7,.4,1) |
| 呼吸 | 每个姿态周期不同，约 2.6–3.4s | ease-in-out，逐帧动画循环 |

呼吸的周期和幅度按姿态分了档，不走统一值：睡着的慢（320ms/帧）、甩头快（120ms/帧）、其余居中。具体帧数列在 `dog/anim.html` 的页面里，16 个各不相同。

## 五、小狗姿态的状态规则

不是随机配图，是由「还差几个条件」决定的。活跃度对应急迫度——不用读文字就能判断急不急。

| 条件状态 | 姿态 | 文件名 |
|---|---|---|
| 已暂停 | 趴下睡着 | `sleep` |
| 还差 2 个以上 | 趴着等 | `lie_down` |
| 还差 1 个 | 坐着笑 | `sit_laugh` |
| 条件全齐 | 站起来抬手 | `beg_stand` |
| 正在响 | 冲过来 | `run_happy` |
| 按了「知道了」 | 坐好看你 | `sit_b` |

代码里的实现在 `prototype.html` 的 `poseByPending(n, paused)`，五行，可以直接照搬。

放置点只有四处，不要铺满：

| 位置 | 尺寸 | 说明 |
|---|---|---|
| 列表页主卡标题右侧 | 96（标题超 13 字缩到 80） | 脚踩在卡片上沿 |
| 详情页标题右侧 | 82 | 不抢内容 |
| 全屏提醒页 09:00 右侧 | 136（建议降到 120） | 唯一带跳动的地方 |
| 空状态居中 | 238（建议降到 140） | 配「它不催你」 |

响铃页点「知道了」时，小狗先从 `run_happy` 弹到 `sit_b`，640ms 后才退回列表。这个延迟是故意的，做出「被回应」的感觉，请保留。

另有 5 个姿态（`walk_fast`、`walk_front`、`stand_left`、`roll_over`、`chase_ball`）自带方向和速度，只做转场，不当静态状态位用。

## 六、明确没做的部分

这几项是留白，不是遗漏，请不要当成已完成：

1. **定位失败、权限申请两个异常状态没有界面**。素材已经备好（`shake` 用于定位失败，`stand_wave` 用于请求权限），缺的是位置和文案。
2. **浅色适配没做**。当前只有暗色一套，`prefers-color-scheme` 亮色下的表现未定义。
3. **暂停态只有视觉，没有数据**。原型里暂停是前端状态，真实的暂停语义（暂停期间条件齐了也不响、下次触发怎么算）需要和后端逻辑对齐。
4. **装饰元素拆不出来**。爱心、汗滴、音符、zzz、草、速度线都和狗焊在同一张 PNG 里，做动画时只会跟着狗一起呼吸，不会自己飘。要做球滚、zzz 上浮，需要画师提供分层文件。
5. **只有 Android**。不做 iOS，不做平板横屏。
6. **不做云同步、不做账号**。数据只在本机，这是产品约束，不是没来得及做。
