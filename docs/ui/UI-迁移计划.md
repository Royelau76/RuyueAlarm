# UI 迁移计划（「条件就绪」方向三）

> 设计交付：2026-10-31，对应 v0.13.0 时期；本计划写于 v0.17.0（2026-11-03）。
> 设计方原文见 [`README-给工程师.md`](README-给工程师.md) 与 [`spec.md`](spec.md)，
> 十张界面稿在 [`screens/`](screens/)，交付板预览见 [`design-board-预览.png`](design-board-预览.png)。

## 一、这套设计的主张

一句话：**让「什么时候、在哪儿、因为什么」比「什么事」更早被看见。**

它诊断的四个问题全是我们的实况：五层信息等权、触发源没有视觉身份、
新建页 7 个折叠区同权平铺、锁屏提醒 1 秒读不懂。

### 三个核心机制

**① 颜色 = 触发源**（不是装饰，是信息；禁止换成单色）

| 时间 | Wi-Fi | 地点 |
|---|---|---|
| `#9BE0CC` 薄荷 | `#BAC3FA` 薰衣草 | `#F4D0A8` 蜜桃 |

底色/层级：夜底 `#18213A`（渐变 `linear-gradient(168deg,#1B2540,#18213A 42%,#212C4C)`）·
卡片 `#26335A` · 卡片高亮 `#2E3C68` · 弹层 `#212C4A` · 轨道 `#3A4874` ·
正文 `#EDF0FF` · 次级 `#B9C2E0` · 辅助 `#A6B1D6` · 亮底深字 `#17273F`

**② 路径组件**（本版最关键，规则只有五条）

1. 段数 = 启用条件数（只用时间就只画一段，不假装有三段）
2. 达成的段用该触发源的色，未达成留暗轨 `#3A4874`
3. 白点 = 「此刻」，停在最后一个达成点上
4. 列表行里退化成**节点序列**（小圆点 + 短线），一行看出几个条件、几个已满足
5. 宽度 < 200dp 时标签全关，只留点和线

**③ 小狗姿态 = 还差几个条件**（活跃度对应紧迫度，不读字也知道急不急）

| 条件状态 | 姿态 | 素材 |
|---|---|---|
| 已暂停 | 趴下睡着 | `dog_sleep` |
| 还差 ≥2 个 | 趴着等 | `dog_lie_down` |
| 还差 1 个 | 坐着笑 | `dog_sit_laugh` |
| 条件全齐 | 站起来抬手 | `dog_beg_stand` |
| 正在响 | 冲过来 | `dog_run_happy` |
| 按了「知道了」 | 坐好看你 | `dog_sit_b` |

放置点只有四处：列表主卡标题右侧 96dp（标题超 13 字缩到 80）· 详情页 82dp ·
全屏提醒页 120dp（设计写 136，**素材不够，必须降**）· 空状态 140dp（设计写 238，**必糊，必须降**）
响铃页点「知道了」时：`run_happy` 弹到 `sit_b`，**640ms 后**才退回列表（故意的"被回应"感，保留）。

### 三条技术红线（README 反复强调，落地时最容易错）

1. **字号不能照抄 px**：原型正文 11.5px 是 412px 画布的视觉等效值 → 真机要 **14–16sp**（+2~3sp）。
   画布基准 412×892，内容区边距 上 14 / 左右 18 / 下 26，卡片圆角 20–24，按钮圆角 18，
   主按钮高 54，主标题 22–26，卡内标题 14–15，正文 12–13，辅助 11–11.5，全屏时间数字 74，
   **最小点击区不小于 48dp**。
2. **小狗素材真实清晰度上限 220×220 物理像素** → 已入库的是 256px WebP（≈上限），
   所以 120dp/140dp 是能用的最大尺寸，再大就是插值糊。
3. **8.7MB 的 WebP 动画不进 APK** → 用代码做呼吸：
   `scaleY 1→1.018→1`、`scaleX 1→0.994→1`（反向）、`pivotY = size × 0.93`（脚底），
   周期按姿态 2.6–3.4s，ease-in-out。

### 动效参数

| 场景 | 时长 | 曲线 |
|---|---|---|
| 页面进入 | 300ms | ease，位移 14px |
| 底部弹层 / 全屏弹窗 | 340 / 380ms | `cubic-bezier(.32,.72,0,1)`，从 100% 上滑 |
| Toast | 280ms | ease，位移 12px + scale .97 回正 |
| 小狗弹入（换姿态） | 420ms | `cubic-bezier(.34,1.56,.64,1)`，带过冲 |
| 小狗跳动（响铃页） | 1.1s × 2 次 | `cubic-bezier(.36,.7,.4,1)` |

## 二、10 张设计稿 ↔ 我们现在 7 屏

| 设计稿 | 现有实现 | 差距 |

| `list` 列表 | `ReminderListScreen` | 重做（含空状态入口） |
| `new` 新建首屏 | `ReminderEditScreen` | 重做：折叠区 → **开关驱动的渐进披露** |
| `adv` 进阶参数 | 同上（下半部分） | 重做 |

## 三、设计需要的、我们现在还没有的数据

| 设计上出现 | 现状 | 补法 |
|---|---|---|
| `alert` 「08:58:12 连上公司-5G / 08:59:40 进入公司 500 米 / 09:00:00 时间到」 | ✅ **可从事件日志推出**（条件达成时刻都在 `event_logs`） | 加一个按窗口查日志的 DAO 方法 |
| `alert` 「已响 4 秒」「共响过 6 次」 | 部分有（对账台账有 `FIRED` 计数） | 响铃页记「响铃开始/结束」两个事件 |
| `detail` 「最近三次：你点了知道了 / 等了 46 秒才点 / 连点两次」 | ❌ 没记 | 新增 `RING_ACK` 事件（动作 + 耗时 + 连点次数） |
| `list` 底部「本周响过 9 次 · 按了知道了 7 次 · 没管 2 次」 | 部分有 | 同上，从 `RING_ACK` 聚合 |

这些都是一次加入、长期有用，正好接在 v0.16 的**对账台账**上。

## 四、分步计划（每步一屏，你截图校准后再往下）

| 步骤 | 内容 | 验收 |
|---|---|---|
| **Step 0** ✅ | 素材入库（`docs/ui/` + `res/drawable-nodpi/dog_*.webp`）+ 本计划 | 体积 3.6MB（不含 zip/动画），小狗 6 姿态共 92KB |
| **Step 1**（样张页） | **只做列表页**：theme token + 路径组件 + 小狗呼吸 + 主卡/行信息层级 | 你截图对比 `screens/list.png`，差距我改；定稿即全项目设计语言 |
| **Step 2** | 响铃页：为什么现在响（路径 + 条件时间线）+ 已响 N 秒 | 截图对比 `screens/alert.png`；顺带补 `RING_ACK` 埋点 |
| **Step 3** | 编辑页：`new` + `adv` + 两个底部弹层 | 对比 `new/adv/sheet-wifi/sheet-place` |
| **Step 4** | 设置页 / 空状态 / 引导页 | 对比 `set/empty` |
| **Step 5** | 详情页（新增）+ 暂停语义 | 对比 `detail/paused`；暂停要先定数据规则 |

**为什么先做列表页**：它一页就用上了色板、路径组件、小狗、字号体系、卡片层级、动效 ——
风险最高也最能定调；做完这一页，后面都是复用。

## 五、待定决策（每步开工前确认，也可以先定）

| # | 问题 | 建议 |
|---|---|---|
| 1 | 亮色主题（设计只做了暗色） | **只保留暗色**，App 内强制暗色。设计的整句话汇靠夜底发光成立，亮色下不成立 |
| 2 | 小狗素材体积 | 已定：6 姿态 256px WebP，共 **92KB**；动画用代码 |
| 3 | 文案用词：「约定」vs「提醒」 | 跟设计走（「新约定」「这条约定」），与产品名"如约"一致 |
| 4 | 是否做暂停 | 到 Step 5 再定；需要真语义（暂停期间条件齐了也不响、恢复后下次怎么算） |
| 5 | 是否新增详情页 | 值得：它是唯一能放「最近三次」「为什么这次没响」的地方 |

## 六、落地约定（吸取 v0.8.x 的教训）

1. **一次只改一屏**，改完立刻出 APK 让你截图 —— UI 我看不到渲染结果，一次改多屏等于赌运气。
2. **像素级跟随设计稿**，但**字号按 Android 体系换算**（+2~3sp），不照抄 px。
3. **先做可用的静态版，再加动效**（动效最后统一加，避免每页都要调）。
4. **不为了 UI 改数据层**：需要新数据时单独加埋点，跟 UI 迁移分开提交。
5. 每步完成后把结论追加到 [`../版本历史.md`](../版本历史.md)。
