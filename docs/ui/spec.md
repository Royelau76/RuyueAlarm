# spec · 如约 App 界面重设计

## 产品是什么

「如约」，安卓端本地提醒工具。当前版本 v0.13.0-m2，自用，不做多设备同步、不上云，数据只在本机。
核心机制：一条提醒可以挂在三种触发源上——**指定时间**、**连上指定 WiFi**、**进入指定地点范围**。
三种可以组合，组合逻辑是「任一满足（或）」或「同时满足（且）」。

参数粒度很细（都来自现有界面，全部要保留）：
- 重复：仅一次 / 每天 / 工作日 / 周末 / 自定义星期
- WiFi：连上后确认 立即·10s·15s·30s（防 WiFi 抖动误触发）
- 地点：触发半径 200·300·500·1000m；进入后停留 立即·1分·3分·5分（防开车经过误触发）
- 冷却：1分钟 / 1小时 / 6小时 / 一天（防反复响）
- 响铃：铃声选择、渐强 关·10s·20s·30s

## 受众与场景

受众是单人：作者自己。但界面要服务三个真实时刻：
1. **通勤路上**——地铁里、开车前，单手、屏幕晃、注意力只有两三秒。代表场景：9:00 到公司提醒开工、到云大医院提醒。
2. **室内**——到家连上 WiFi 提醒换鞋、欢迎回家。屏幕近、光线暗、可以停留。
3. **被提醒的一刻**——锁屏弹全屏提醒。此时用户不在 App 里，界面必须 1 秒读懂。

## 这一版要解决什么（诊断）

现有界面的问题不在配色，在信息结构：

1. **五层信息等权。** 标题、条件 chips、下次触发时间、副文案、开关挤在一张卡里，没有主次。扫视时眼睛落在蓝色开关上，而不是「什么时候会响」。
2. **触发源没有视觉身份。** 三种触发全靠文字 chips（「09:00」「地点 公司」「WiFi ×2」）表达，必须逐字读。而「这条靠什么触发」恰恰是这个 App 和普通待办的区别。
3. **新建页第一屏就被淹没。** 七个折叠区同权平铺，20+ 参数，用户看不出哪些是必填、哪些是进阶。
4. **锁屏提醒文案层级平淡。** 「提醒 / 测试 / 一句话 / 三个按钮」全部同尺寸，扫一眼不知道发生了什么。

## 三方向共同的输出规格

- 设备：AndroidFrame，内容区 412×892；设备框用技能 assets/android_frame.jsx，不手写状态栏与挖孔
- 展示板：1680×1050，三版各不相同（主次 / 流程串联 / 语境底）
- 每版 5 屏：① 提醒列表 ② 新建提醒（首屏）③ 新建提醒·进阶参数（同一页下层）④ 锁屏提醒 ⑤ 设置
- 每台手机可交互：tab / 开关 / 展开折叠 / 抬起底部弹层
- 中文文案，正文不小于 14px，标签不小于 12px，对比度 ≥4.5:1
- 真实数据（来自现有界面），不用占位：

| 提醒 | 条件 | 下次 | 副文案 |
|---|---|---|---|
| 开工提醒 | 09:00 且 地点「公司」 | 10-30 09:00 | 开工开工！ |
| 到家提醒 | WiFi ×2 | — | 欢迎回家！ |
| 拿空气炸锅的配件 | WiFi | — | — |
| 到医院了 | 地点「云大医院」 | — | — |
| 刮胡子 | 22:30 且 WiFi | 10-31 22:30 | 刮胡子！ |

## 情感基调

不打扰。这个 App 一天只出现两三次，出现时必须有用，不出现时必须不存在。
所以视觉上要克制、要有系统感（用户的参照系就是 iOS 自带 App），但克制不等于没有主张——三种触发源要有清楚的身份。

## 已知约束

- 平台安卓，但设计语言走 iOS 系统 App 的语汇（用户明确偏好）；设备框保持安卓形态，不伪装成 iPhone
- 无品牌资产：没有 logo、没有主色。色彩从「如约」这个词和三种触发源里长出来
- 不做多设备同步、不上云 → 设置页不需要账号体系，这是它比同类产品干净的地方，要在设计里体现（而不是用「本地存储」当免责声明塞在底部小字）

## 三版统一的一句话

让「什么时候、在哪儿、因为什么」比「什么事」更早被看见。
