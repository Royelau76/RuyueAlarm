# M2 · 地点选点方案（地点收藏 + 地图选点）

> 目标：给「到地点提醒」提供两种选点方式 —— **收藏复用**（去过的地点点一下就选）和
> **地图选点**（没去过的地方也能提前设）。
> 围栏判定**完全不动**：仍然是自研 `LocationManager`，地图只负责"返回一个经纬度"。

## 0. 一句话结论

- **围栏代码一行不改**：`Reminder.placeLat/placeLon/radiusMeters/placeName` 四个字段已有，
  `TriggerEngine` 只认坐标。新增的都只是"往这四个字段填值"的 UI 与数据。
- 地图 SDK **不需要新 key**：高德一个 Android 平台 key 同时开通地图/定位/导航 SDK
  （现有 key 的"可用服务"里已经包含 Android地图SDK）。
- 顺手**移除**已结案的高德**定位** SDK（2.3MB），换成高德**地图** SDK（轻量版约 2~3MB）
  → APK 体积基本不变。

## 1. 设计原则（三条）

1. **快照，不是引用。** 提醒里存的是坐标快照，不是"收藏地点 id"。
   这样删掉/改掉收藏地点，不会悄悄改变已有提醒的触发范围。
2. **选点与判定分离。** 地图 SDK 只做"显示地图 + 返回坐标"；
   定位、围栏判定、停留计时仍然全用我们自己的 `LocationHelper` / `TriggerEngine`
   —— 地图页里"跳到我当前位置"也调 `LocationHelper`，不调高德定位。
3. **前台零负担。** 地图页只在前台存在（Activity 生命周期内），
   对耗电影响可忽略 —— 与已结案的"高德定位围栏"（后台持续定位，实测 9.8%）是两件事。

## 2. 数据模型

### 2.1 新表 `saved_places`（提醒库 `ruyue_reminders.db`，版本 3 → 4）

```kotlin
@Entity(tableName = "saved_places")
data class SavedPlace(
    @PrimaryKey(autoGenerate = true) val id: Long = 0,
    /** 显示名：公司 / 家 / 医院 */
    val name: String,
    val latitude: Double,
    val longitude: Double,
    val radiusMeters: Int = 300,
    /** 可选备注：地图选点时如拿到地址就存这里，拿不到留空 */
    val address: String = "",
    val createdAt: Long = System.currentTimeMillis(),
    /** 最近一次使用时间，列表按它倒序（常用的排前面） */
    val lastUsedAt: Long = 0,
)
```

- 迁移 `MIGRATION_3_4`：`CREATE TABLE IF NOT EXISTS saved_places(...)`
- ⚠️ 迁移必须用老办法验证：离线 sqlite 建 v3 结构 → 插一行 → 跑建表语句 →
  与 Room 生成的 `ReminderDatabase_Impl` 期望 schema **逐列比对**（v2→v3 就是这么验的）
- 不去动日志库 `ruyue.db`（永远 v1，证据不受影响）

### 2.2 提醒实体

**不改**。`placeName / placeLat / placeLon / radiusMeters / placeDwellSeconds` 已齐。

## 3. 界面

### 3.1 编辑页 ③「到地点提醒（进入范围）」改成

```
③ 到地点提醒（进入范围）              公司 · 300m · 停留 60s
─────────────────────────────────────────────────────
 [启用 ●]

 地点名称  [ 公司                     ]
 当前坐标  31.23105, 121.47321 · 半径 300m

 ╭───────────────╮ ╭───────────────╮
 │ 用当前位置     │ │ 在地图上选     │   ← 新增第二个入口
 ╰───────────────╯ ╰───────────────╯

 收藏的地点（点一下就用）：
 [公司 300m] [家 500m] [医院 200m]        ╭──────────╮
                                          │ 存为收藏 │
 触发半径  300 米  [200] [300] [500] [1000] ╰──────────╯
 停留确认  60 秒   [30] [60] [120] [300]
```

- **点收藏 chip** → 把 name / 坐标 / 半径 一次性填进草稿，并更新该收藏的 `lastUsedAt`
- **存为收藏** → 用当前草稿的地点（名字为空则弹窗要求填）存一条 `SavedPlace`；
  同名则覆盖（不重复堆）
- **长按 chip** → 弹「删除这个收藏？」二次确认
- 收藏列表为空时显示一句提示：「在地图上选一次或点『用当前位置』后，可以存为收藏」

### 3.2 地图选点页 `MapPickerScreen`

```
┌────────────────────────────────┐
│ ← 在地图上选点         [用当前位置] │
│                                │
│        （高德地图）              │
│                                │
│         ╭─────────╮            │  ← 半透明圆 = 触发半径，随半径变化
│         │    ✛    │            │  ← 准星固定在屏幕中心
│         ╰─────────╯            │
│                                │
│  点击地图 = 把圈移到那里          │
│                                │
│ 地点名称  [ 公司              ]  │
│ 触发半径  [200][300][500][1000] │
│ 中心点    31.23105, 121.47321   │
│  ╭──────────────────────────╮  │
│  │          确定             │  │
│  ╰──────────────────────────╯  │
└────────────────────────────────┘
```

- 进入时：有草稿坐标就以它为中心，否则以「用当前位置」为中心
- **两种交互都支持**：点击地图（把准星/圆圈移到点击处）+ 拖动地图后用中心点
- 圆圈的屏幕半径 ↔ 米 的换算用 `Projection.toPixels(latLng, out)` 算一次像素/米比例
- 「确定」→ 直接写回 `ReminderViewModel` 的草稿（两个页面共用同一个 VM，无需回调传参）→ 返回
- 隐私合规：`MapsInitializer.updatePrivacyShow/updatePrivacyAgree`（和定位 SDK 同理，首次用前调）

## 5. 风险与验证（先做验证，再写 UI）

| 风险 | 应对 |
|---|---|
| **轻量版地图 SDK 的 API 面不确定**（能不能点击取坐标/算像素比例） | 下载后先 `javap` 读真实签名（上次凭记忆写围栏，包名/参数全错，就是靠 javap 纠正的）。若轻量版不够用 → 退到 3D 版（+2~4MB） |
| **数据库迁移写错会启动即崩** | 离线 sqlite 验证 + 与 Room 期望 schema 逐列比对 |
| **地图 SDK 隐私合规** | 首次进入地图页前调 `updatePrivacyShow/Agree`；上架需在隐私政策里声明（自用先记着） |
| **地图选点的精度错觉** | 地图上选不到"楼层/门口"，所以半径建议 ≥200m（页面默认 300m）；文档里写清楚 |
| **APK 体积** | 定位 SDK（2.3MB）退役 + 地图 SDK（2~3MB）加入 ≈ 持平；若用 3D 版则 +2~4MB |
