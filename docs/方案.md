# 如约 · 技术方案

> **文档状态（2026-10-30 更新）**：本文是 M0 之前的**初始技术方案**，保留作决策记录。
> 实现过程中有三处偏离，当前口径以 `CLAUDE.md` 为准：
> 1. **地理围栏改为自研**（系统 `LocationManager`）；高德定位 SDK 只在 v0.9.0 做过实验，已于 v0.13.0 整包移除；
> 2. **地图选点不做**，改为「用当前位置」+ 地点收藏 + 按地址找（高德 **Web 服务 API**，不是 SDK）；
> 3. 精确闹钟用 `USE_EXACT_ALARM`（`SCHEDULE_EXACT_ALARM` 在 Android 14 上用户无处授权）。
> 下文凡与这三点冲突的段落，以本状态说明为准。

事项提醒闹钟：**到点提醒** + **到达指定地点提醒**。地点确认支持两条通路：
**连上指定 WiFi**（读 SSID/BSSID）与**进入指定地理范围**（**自研围栏**，系统 `LocationManager`；原计划高德，已放弃）。

- 目标机型：小米 15 Ultra（HyperOS，国行默认无 Google 服务框架）
- 阶段目标：先自用 → 成熟后上小米应用商店
- 明确不做：多设备同步、云账号（至少 M3 之前不做）

## 一、总体结构

```
                  ┌──────────────────────────────┐
   时间触发 ──────▶│ AlarmManager.setAlarmClock   │──┐
  (精确、最可靠)    │ + 全屏 Activity + USAGE_ALARM │  │
                  └──────────────────────────────┘  │
                                                    ▼
  WiFi 触发 ──────▶┌──────────────────────────────┐  ┌──────────────┐
  (省电、室内准)    │  常驻前台服务「哨兵」          │─▶│ 统一响铃管线  │
                  │  · NetworkCallback（事件驱动） │  │ 响铃/稍后/完成│
  位置触发 ──────▶│  · 心跳（证明自己没被杀）      │  │ + 触发日志   │
  (室外准、耗电)    └──────────────────────────────┘  └──────────────┘
                              ▲
                        Room（事件日志/去抖/冷却状态）
```

三条通路汇到**同一个响铃管线** —— 这是保持代码简单的关键，别让每种触发各写一套 UI。

**这个产品 80% 的成败不在功能，而在「提醒到底会不会响」。**

## 二、三种触发的选型

| | 时间 | WiFi | 位置 |
|---|---|---|---|
| 用什么 | `AlarmManager.setAlarmClock()` | 前台服务 + `registerNetworkCallback` | 自研 `LocationManager`（原计划高德 `AMapGeoFenceClient`，已放弃） |
| 权限 | **不需要**精确闹钟权限 | 位置权限（读 SSID） | 精确定位 + **始终允许**后台定位 |
| 可靠性 | ★★★★★（Doze 也照响） | ★★★☆ | ★★★☆ |
| 耗电 | 几乎为零 | 低（事件驱动） | **实测 0.03%**（4 天窗口 ≈ 0.02mA） |
| 延迟 | 秒级 | 秒级~1 分钟 | **实测 61s ~ 3m19s** |
| 中国 ROM 风险 | 低 | 中（息屏关 WiFi） | 中（无 GMS：不用 FusedLocationProvider，靠自研两层判定） |

### 时间触发
- 用 `setAlarmClock()` 而非 `setExactAndAllowWhileIdle()`：不需要精确闹钟权限、免除 Doze、
  状态栏显示闹钟图标。
- 必须监听 `BOOT_COMPLETED` / `MY_PACKAGE_REPLACED` / `TIME_SET` / `TIMEZONE_CHANGED` 重排闹钟，
  否则重启后提醒全部消失。

### WiFi 触发
- 用 `NetworkCallback` 监听 `TRANSPORT_WIFI` 的连上/断开，**事件驱动、不轮询**。
- 广播这条路走不通：`CONNECTIVITY_ACTION` / `NETWORK_STATE_CHANGED_ACTION` 在 Android 7+
  不会投递给清单里注册的静态接收器，进程一死就收不到 → 必须靠前台服务撑住进程。
- 读 SSID 需要位置权限（Android 8.1+）；后台读还要「始终允许」。Android 13+ 的
  `NEARBY_WIFI_DEVICES(neverForLocation)` 能替代到什么程度 —— **正是 M0 第 1 项要测的**。
- 匹配键：**默认 SSID，BSSID 作为可选精确项**。家里/公司一个 SSID 挂多个 AP（mesh）时
  BSSID 会变，用它反而漏触发。
- 必须去抖：连上后等 10~30 秒确认仍在线才触发；同一条提醒**默认一天只触发一次**，
  触发后进冷却。否则家里 WiFi 一天重连 20 次就响 20 次。
- 部分 ROM 息屏关 WiFi 省电 → 引导用户打开「始终保持 WiFi 连接」。

### 位置触发（自研，v0.3.0 起；高德方案已放弃）
- 国行无 GMS → 不用系统 Geofencing API，也用不了 FusedLocationProvider；
  改用系统 `LocationManager` **自研围栏**：零 key、零第三方 SDK、少一块隐私合规。
- **两层判定**（v0.4.0 省电重构）：连续监听只挂网络定位（60s / 200m）定「候选区」；
  进入候选区后，停留复核**短暂**开 GPS 做精确确认（优先精度 ≤150m，三层兜底）。
- **停留判定要主动取新位置复核**（v0.3.1）：`minDistance` 下站着不动系统不给回调；
  半径加 20% 滞环防边界抖动；每次到访只提醒一次（v0.4.1）。
- 实测：功耗 **16.23% → 0.35% → 0.03%**；到访→响铃 **61s ~ 3m19s**；复核失败 2 次/2 天。
- UI 上存 `lat/lng + 半径 + 地点名`；**地图选点已明确不做** ——「用当前位置」+ 地点收藏已覆盖，
  「按地址找」走高德 **Web 服务 API**（HTTPS+JSON，不是 SDK）。
- 历史：v0.9.0 曾接入高德定位 SDK 做 M0 ④ 实验，零触发 + 9.8% 耗电；v0.12.0 查明真实原因是
  App 缺 `INTERNET` 权限（**假证据**），v0.13.0 整包移除该 SDK（APK 12.2 → 9.83MB）。

## 三、响铃管线（三种触发共用）

1. 触发 → 写 `event_logs`（防重复 + 留证据）→ 启动响铃
2. 全屏 Activity：`setShowWhenLocked` + `setTurnScreenOn` + `requestDismissKeyguard`
3. 音频用 `AudioAttributes.USAGE_ALARM`（走闹钟音量，默认穿透勿扰）+ 震动
4. 三个动作：完成 / 稍后提醒（5·10·15 分钟）/ 忽略
5. 兜底：全屏意图被拒时降级为高优先级横幅通知

两个必知坑：
- **全屏意图只在锁屏/息屏时全屏弹出**；用户正用手机时只出横幅（系统行为，改不了）。
- HyperOS 有独立的「后台弹出界面」权限，不开则锁屏闹钟根本弹不出来。

## 四、数据模型（M1 起）

```
reminders      提醒主体：id, title, note, enabled, snooze_minutes, cooldown_rule
triggers       触发器：id, reminder_id, type(TIME|WIFI|PLACE),
               time_spec | ssid/bssid | lat,lng,radius, active_window, enabled
trigger_logs   触发日志：id, trigger_id, fired_at, action, source
geofences      去重后的围栏：id, lat, lng, radius, ref_count
event_logs     M0 已有：服务心跳 / WiFi 事件 / 闹钟事件（排障依据）
```

`event_logs` / `trigger_logs` 不只是历史记录，更是**排障依据**：用户说「没提醒」时，
要能一眼看出是没触发、还是触发了没弹出来。

## 五、权限清单

| 权限 | 用途 |
|---|---|
| `POST_NOTIFICATIONS` | 常驻通知 + 提醒 |
| `RECEIVE_BOOT_COMPLETED` | 重启后重排闹钟 |
| `ACCESS_FINE_LOCATION` | 读 SSID、定位 |
| `ACCESS_BACKGROUND_LOCATION` | 后台/锁屏时的位置触发 |
| `NEARBY_WIFI_DEVICES` | WiFi 相关（能否替代位置权限待 M0 结论） |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE` | 哨兵服务 |
| `WAKE_LOCK` | 响铃期间保持唤醒 |
| `USE_FULL_SCREEN_INTENT` / `USE_EXACT_ALARM` | 全屏闹钟 / 精确闹钟（Android 13+ 安装即授予；`SCHEDULE_EXACT_ALARM` 只作 12~12L 兼容保留） |

上架小米商店时，定位类权限需要**单独说明用途** + 隐私政策。

## 六、必须提前告诉用户的硬限制

- 点「强行停止」后所有触发失效，直到用户再次打开 App（Android 硬限制）
- 深度 Doze 下**位置到达检测可能延迟几分钟**；时间闹钟不受影响
- 轮询兜底在 Doze 里最快约 9 分钟一次（`setExactAndAllowWhileIdle` 限流），不能当主方案
- **iOS 未来做不了「连 WiFi 触发」**（普通 App 拿不到当前 SSID）→ 触发器要做成平台无关的数据结构，
  iOS 版只保留时间 + 地理围栏
- 若以后要上纯血鸿蒙 NEXT，Android APK 不能直接跑，需单独适配
